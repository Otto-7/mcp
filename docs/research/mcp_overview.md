## Роли host / client / server
MCP использует архитектуру из трех участников. 

### Host
Host - приложение с LLM, которое координирует работу Client. 
Ф-ции:
- Предоставляет пользовательский интерфейс
- Координирует работу LLM с сервером
- Создает client
- Управляет правами доступа
 
### Client  
Client - компонент хоста, имеющий связь с единственным сервером.
Ф-ции:
- Изолирует серверы друг от друга
- Маршрутизирует сообщения между хостом и сервером 
- Проверяет совпадение версий

### Server
Server - программа, подключенная к хосту через протокол MCP.
Ф-ции:
- Объявляет поддерживаемые примитивы (tools, promts, resources)
- Обрабатывает запросы Client
- Возвращает результаты в структурированном виде

## Транспорты (stdio, HTTP)
MCP состоит из двух слоев: уровень данных и транспортный уровень.
Уровень данных определяется протоколом на основе JSON-RPC 2.0
Транспортный уровень определяет, как передается сообщение между клиентом и сервером: через канал stdio или HTTP.

### Транспортный механизм stdio
Используется для запуска на той же машине, что и хост. Реализуется через ввод и вывод в терминале.  

### Потоковый транспортный механизм HTTP
Используется для удаленного взаимодействия с сервером, который должен быть доступен несколькими пользователями или приложениями. Поддерживает стандартные методы HTTP-аутентификации.

## Примитивы (tools, resources, prompts)
Примитивы - это то, чем сервер и хост обмениваются с друг другом.
- Tools - это функции, которые LLM может вызывать для выполнения действий.
- Resources - это структурированные данные сервера (содержимое файлов).
- Promts - шаблоны, которые помогают структурировать ответ LLM.
